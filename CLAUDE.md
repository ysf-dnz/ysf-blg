# ysf-blog — "Bilgi Ödüldür" Topluluk Platformu

Kişisel blog + üyelikli öğrenme topluluğu. **Kitaplar satılmaz, emekle açılır**:
oku → üret (yazı/quiz/görev) → puan kazan → yeni kitap aç. Medium (editör,
takip, beğeni) + Skool (feed, seviye, harita, classroom) + Kahoot (süreli quiz)
+ Jira (kulüp Kanban'ı) desenleri tek platformda.

## Stack
- **Astro 5** server-mode (Vercel adapter) + Tailwind v4 (`src/styles/global.css` @theme; `motion.css` animasyon kütüphanesi — reveal/stagger/ticker `src/features/motion/init.ts`)
- **Clerk** auth (`@clerk/astro`; Google girişi; TR yereli). DİKKAT: Clerk `PUBLIC_CLERK_PUBLISHABLE_KEY` bekler, Vercel entegrasyonu `NEXT_PUBLIC_*` verir → eşleme `.env` dosyasında ve Vercel env'lerinde. `vercel env pull` yalnız `.env.local`'ı ezer.
- **Neon Postgres + Drizzle** (`src/db/schema.ts` ~25 tablo; `db` istemcisi TEMBEL Proxy — birim testler env istemez). Şema değişikliği: `node --env-file=.env.local node_modules/.bin/drizzle-kit push`
- İçerik: Keystatic (yalnız `npm run admin`), 884 kitap `src/data/books.json` (id = Drive fileId), Pagefind arama (server-mode'da `dist/client` indexlenir — postbuild)

## Kurslar — Faz 1 (2026-10-11; PRD `docs/prd/kurs-topluluk-ekosistemi.md`, ADR `docs/adr/0001-*`)
- **Terim "kurs"** (eski ders/eğitim; `CONTEXT.md`). Sayfalar `ToplulukLayout`'ta; kurs sayfası **mıknatıs**: misafir müfredatı ve İLK öğeyi görür, gerisi kilit + `SignInButton forceRedirectUrl=mevcut URL` (header'ın `/uye/hosgeldin` zorlaması kullanılmaz). Members-only üye yazısı kurs içinde de kilitli; pending/draft/hidden kurs yalnız üretici+admin (diğerine 404, `noindex`).
- **`awardPoints` artık `number` döner** (yazılan delta; 0 = idem ya da tavan). Opsiyonel `tavan` {reasons, since, limit} `db.batch`'te `pg_advisory_xact_lock(user_id)` + `INSERT…SELECT least(delta, kalan)` yazar (tek transaction, ADR K1.5 — kilitsiz tek SQL paralel isteklerde tavanı N kez aşıyordu); `tavanIcin(reason)` varsayılanı OTOMATİK uygular (üretici günlük 100, ek kaynak 45, en iyi cevap 30, kurs bitirme kayan 7 günde 100) — çağıran tavanı unutamaz. `begeniPuaniVer` yorum beğenilerini de aynı günlük sayaca katar.
- **Bekleyen puan `pending_points`** (ledger DIŞI → seviyeye sayılmaz): `puanOlayi()` kaynak hesap 24 saatten gençse bekleyene (`matures_at`) yazar; kesinleşme sırası ZORUNLU **önce `awardPoints`, sonra status** (`bekleyeniKesinlestir`, onarım `yazilan`'ı ledger'dan okur). Cron `bekleyen` + `/uye` panosunda tembel `bekleyenleriIsle(now, userId)`.
- **İade** `revokePoints()` = negatif `admin_adjust` (`iade:{reason}:{refId}`), seviye/lider DÜŞMEZ (toplamlar delta>0), bakiye düşer.
- **Kurs motoru `api/uye/egitim.ts`** (rota adı tarihsel): öğeler ÖNCE çözülür (≥3 geçerli; yalnız KENDİ yayınlı yazın), `join` (üretici katılmaz), `complete` katılım şart → aktivasyon/bitirme `UPDATE … WHERE … IS NULL RETURNING` (C ilkeli), 3. aktivasyonda `course_launched`, asgari süre öğe×60 sn (`asgariSureGectiMi`), `accept-answer`/`resource`/`resource-review`/`rate` tek-SQL sahiplik koşullu. Yorum/beğeni `feed.ts`'te (`courseItemId`/`commentId` dalı, aynı 30 sn freni). Şikâyet `sikayet.ts`: 3 farklı Sv4+ → gizle (sayım WHERE'de); admin kuyruğu kaldır(+iade)/geri aç.
- **Yönlendirme kuralı**: Astro yönlendiricisi HARF DUYARLI, **Vercel kenarı HARF DUYARSIZ** (canlıda ölçüldü: `/DERSLER` → 301; `/d/kod` da `/D/[kod]` 301'ine takılır), middleware yalnız SSR rotalarda → 301'ler `astro.config.mjs redirects` (dinamik destination VAR OLAN rota anahtarıyla birebir eşleşmeli, query taşıyamaz). Büyük harf yönlendirmesinin hedefi kaynağın küçük harfli hâliyle AYNI yol olamaz (canlıda sonsuz döngü) → `/d/q/`, `/t/q/`, `/c/q/` deseni; davet kanalı yoldan değil `davetKanali(kodHam)`'dan. **Tuzak:** `"/D/[kod]"` gibi büyük harfli redirect anahtarı Astro'da küçük harfe çevrilir ve aynı anahtarlı `src/pages/d/[kod].astro` sayfasını rota listesinden DÜŞÜRÜR (404) → sayfa rest param olmalı (`d/[...kod].astro`). Sitemap: `filter` `/uye/*`'yi düşürür (`/uyeler` kalır), `[slug]` sayfaları `sitemap-kurslar.xml` (SSR, `customSitemaps`).
- **DİKKAT dev = canlı Neon DB** (`.env.local` = `vercel env pull`): `drizzle-kit push` ve backfill DOĞRUDAN canlıya uygulanır; yalnız ek (additive) değişiklik, `slug` NOT NULL'a geçiş backfill sonrası ikinci push'la yapıldı (`canli-index-uygula.sql` ADIM 5).
- **Testler**: `tests/unit/kurs-ekonomi.test.ts` (saf), `tests/integration/ekonomi-db.test.ts` (yalnız `POSTGRES_URL_TEST` ile: tavan SQL yarışı, idem, kesinleşme onarımı, iade — 7/7 gerçek Neon'da), e2e `kurslar.spec` (misafir) + `kurs.spec` (auth). **Vite tuzağı**: `.astro` yorumuna literal `<script>` yazma — bağımlılık taraması çöker, ~60 sn sonra tam sayfa reload testleri düşürür (D3Chart'ta yaşandı).
- Davet çerezi hotfix: `Base.astro` inline script `?ref=` → `ysf_ref` (statik sayfalarda middleware koşmaz; canlıda davet zinciri kırıktı).
- **Davet (Faz 2) güvenlik kuralları**: `/d/` çerezleri yalnız `sec-fetch-dest: document`; kullanıcı URL'sinden görsel çeken her yer `kart.ts dataUri` desenini kullanır (redirect error, 2 MB, sharp normalize). IP hash'i `CRON_SECRET` HMAC'li.

## Etkinlik — Faz 3 (2026-10-11; dal `faz3-etkinlik`, issue'lar #25–#30)

- **Kayıt puan ÜRETMEZ; puan yalnız doğrulanmış girişten** (AC-15). `girisYap` ADR K1.4: tek SQL `UPDATE … WHERE checked_in_at IS NULL RETURNING` → satır döndüyse "geldi", değilse "zaten". Ödül zinciri (`girisOdulleri`) **YALNIZ girişi yazan istekte** koşar ("zaten"de yeniden koşturma: tavana takılıp 0 yazılan ödül pencere boşalınca ödenirdi): `event_attended` refId **`String(eventId)` AYNEN** (eski RSVP ödülü ikinci +10'u engeller) → davetliyse `event_invite_welcome` (anında) → davet edenin bekleyeni `puanOlayi` (genç hesap → `matures_at`).
- **Ödül zinciri yalnız HERKESE AÇIK etkinlikte** (`etkinlikAcikMi` / `etkinlikGorunurSql`): onay bekleyen topluluk etkinlik AÇAMAZ (admin hariç; her üye başvurup anında başkan olur) ve gizli etkinlikte `kayitOl`, `girisYap`, `etkinligiDegerlendir`, `etkinlikSonrasiIsle` işlemez. Yeni bir ödül/kayıt yolu eklerken bu kapıyı unutma.
- **Etkinlikler ARASI tavan** `tavanIcin`'de: `event_attended` 70/7g, `event_hosted`+`event_well_rated` ortak 1000/7g (etkinlik başına frenler etkinlik sayısını sınırlamıyordu). **Elle girişler düzenleyen payına sayılmaz** (`girisSayisi`: `checkin_method is distinct from 'manual'`). Düzenleyen listesini yalnız açan/admin, kapı açılışına kadar değiştirir; etkinlik başına ≤ 20 görevli.
- **GET ile kayıt YOK** (etkinlik): `?kayit=1` yalnız ipucu bandı; kayıt POST ile (iki dokunuş). `sec-fetch-site` freni aynı kökenli `<img>` (kurs kapağı, markdown görseli), ClientRouter hover-prefetch'i ve uygulamadan açılan bağlantıyı DURDURMAZ. Davet çerezi yedeği (`?d=`) yalnız `belgeGezintisiMi` (lib/urls.ts) ile. Kurs `?katil=1` de GET'le YAZMAZ (Fable 2026-10-12): ek dokunuşsuz katılım (AC-5) NİYETLE — misafirin "Katıl" düğmesi `sessionStorage ysf_niyet=katil:{kursId}:{ms}` yazar (30 dk), girişten dönüşte sayfa betiği `form[data-katil-formu]`'nu POST'lar (`?b` korunur; Astro köken kontrolü; <img>/prefetch betik çalıştırmaz, dışarıdan gelen bağlantı niyet yazamaz); niyet yoksa `?katil=1` yalnız ipucu bandı + bir dokunuş (Astro yönlendiricisi hash'siz aynı adrese de gezinir — "aynı adrese gezinmez" iddiası YANLIŞTI). `getIleYazilabilirMi` SİLİNDİ. **Yeni bir GET akışı durum DEĞİŞTİRMEMELİ** (kalan tek GET yazıcı `/c/q/` dönen QR: 30 sn HMAC token + same-site — Opus'a not). Aynı inceleme: `?ref=` middleware'i yalnız `belgeGezintisiMi` (aynı kökenli `<img>` platform atfını eziyordu; ClientRouter gezintisini `Base.astro` betiği `astro:page-load`'da karşılar) ve üye markdown'ında bağlantı/görsel hedefi İZİN LİSTESİ (`markdown.ts GUVENLI_HEDEF`: https?://, `/…`, `#`, mailto: — `javascript:`/`data:` ile aynı kökende betik = niyet/çerez/POST ile rızasız katılım).
- **Giriş penceresi = kapı (başlangıç − 60 dk) → bitiş; bitişten sonra giriş YAZILMAZ.** Sebep: davet bekleyeni bitişte düşer (AC-19) ve `puanOlayi` düşmüş satıra bakmadan öder → pencere `girisPenceresinde`'de kapanmak zorunda. `ends_at` boşsa başlangıç + 2 saat (`etkinlikBitis`).
- **Kontenjan**: `kayitOl` = `db.batch([pg_advisory_xact_lock(31, eventId), INSERT…SELECT … WHERE count < capacity AND kayıt açık])` — kilitsiz tek SQL paralelde kapasiteyi N kez aşıyordu (entegrasyon: 8 paralel → TAM 3). ⭐ yalnız yeni kayıtta ve `spendPoints` kestiyse.
- **Kendine puan yok**: düzenleyen (host = `events.created_by` ∪ `event_staff.role='host'`, açan + en çok 3) kendi etkinliğinde giriş ve davet puanı almaz, girişi `event_hosted` sayımına girmez, etkinliğini değerlendiremez. Görevli (scanner) düzenleyen DEĞİLDİR. Kontroller hem kayıtta (bekleyen açılmaz) hem girişte (ödenmez) — biri atlanırsa `puanOlayi` genç yolda yeni bekleyen açar.

- **İmzalar** (kolonsuz, ADR K6): bilet `{rsvpId}.{base32(HMAC("t:"+rsvpId))}`, dönen QR `base32(HMAC("c:"+eventId+":"+pencere))` (30 sn; içindeki + önceki pencere). Sır `CRON_SECRET`, **yedek yok** (eksikse hata). Aynı sırrın üç kullanımı önekle ayrılır: bilet `t:`, dönen QR `c:`, IP/UA takma adı `kisaHash` `h:`.

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:
- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
